Entity relationships (SQLite)
GK Trucking Services 2.0

Engine
- SQLite (default Laravel create-project DB).
- Use INTEGER for PKs/FKs, REAL for money and coordinates, TEXT for strings/datetimes/JSON.
- Enforce referential integrity with FOREIGN KEY constraints (enable PRAGMA foreign_keys = ON).
- Soft delete: archived_at TEXT NULL on domain tables (except activity_logs).
- Booleans: INTEGER 0/1 (e.g. bookings.is_locked).

---

ER overview (text)

users
  │
  ├──< bookings.customer_id          (1 customer : many bookings)
  ├──< bookings.driver_id            (1 driver : many bookings; nullable until accept)
  ├──< invoices via bookings
  ├──< ratings.customer_id
  └──< activity_logs.user_id

vehicles
  └──< bookings.vehicle_id           (1 vehicle : many bookings over time; one active in_use)

pricings
  └── (logical) bookings.vehicle_type + bookings.payout snapshot
      No FK required; match by vehicle_type string. Snapshot amount on create.

bookings
  ├── 1:1 eirs.booking_id            (PK/FK)
  ├── 1:1 pods.booking_id            (PK/FK)
  ├── 1:1 invoices.booking_id        (UNIQUE FK)
  └── 1:1 ratings.booking_id         (UNIQUE FK)

settings
  standalone key-value (booking_seq, company, map center)

activity_logs
  polymorphic-style subject_type + subject_id (no hard FK to every table)

Cardinality

User (customer)  1 ─── *  Booking
User (driver)    1 ─── *  Booking          (nullable driver_id until accepted)
Vehicle          1 ─── *  Booking          (nullable vehicle_id until accepted)
Booking          1 ─── 1  Eir
Booking          1 ─── 1  Pod
Booking          1 ─── 1  Invoice
Booking          1 ─── 1  Rating
User             1 ─── *  ActivityLog
Pricing          1 ─── *  Booking          (logical via vehicle_type; payout copied)

---

Foreign keys (recommended)

bookings.customer_id  → users.id
bookings.driver_id    → users.id
bookings.vehicle_id   → vehicles.id
eirs.booking_id       → bookings.id   ON DELETE CASCADE (or restrict + soft delete)
pods.booking_id       → bookings.id
invoices.booking_id   → bookings.id
ratings.booking_id    → bookings.id
ratings.customer_id   → users.id
activity_logs.user_id → users.id

SQLite note: ON DELETE CASCADE works when foreign_keys are on. Prefer soft-delete on bookings and leave child rows; cascade only if hard-deleting.

Not modeled (dropped / computed)

- Driver clearance (dropped from product)
- Live GPS track points (static Mapbox route only)
- earnings_reports table (compute from completed bookings.payout)
- Separate customers / drivers / admins tables (unified users.role)
